# 学习全流程审查

遵守根 [AGENTS.md](../../../AGENTS.md) 及记忆协议。本技能参考 hdims 的全周期流程推演方法，审查对象改为课程和学习进度。

## 开始：输入与模式

从对话确定审查目标、指定入口／环节、重点风险、验证限制及产物要求；其余信息按下表查找，不要求用户预先整理文件清单。

| 输入 | 来源与用途 |
|---|---|
| 应有行为 | 目标需求和学习业务文档；用于判断实现是否偏离要求 |
| 当前基线 | Git 状态、可达入口及其调用方；用于限定结论对应的代码 |
| 场景事实 | 模型、字段和实际分支约束；用于构造合法模拟输入 |
| 验证条件 | 用户限制、已有检查和可用隔离环境；用于判断是否值得运行最小验证 |

- 全流程审查默认覆盖开课至下一课；指定局部范围时只追踪其必要前置、后续与副作用，明确未覆盖环节。
- 静态审查以证据与发现为产物。用户同时授权修复时，保留发现依据并衔接实施；不把此技能当作重复确认或停止已授权工作的理由。
- 普通功能说明、单个符号查询或纯文档编辑不需要启动完整账本；按根规范的对应模式处理。

## 1. 范围与证据

- 审查默认只读业务源码，可按任务要求生成报告并记录有价值增量；审查本身不授权顺手改业务或真实学习库。
- 记录分支/commit/dirty 状态、时间与覆盖范围；工作区相关代码变化后核对证据是否仍有效。
- 读取文档索引、实施状态、目标需求、学习算法及命中指南，按当前模拟步骤扩展阅读，不先平铺所有模块。
- 区分 `代码事实`、`文档期望`、`基于事实的推断`、`证据不足` 和 `模拟输入`。状态名/文件名/测试名不能证明流程闭环。
- 关键结论引用路径和方法/行号；静态审查不证明真机、插件输出和所有并发时序。
- 声称“未找到实现／入口”时，记录搜索范围、相关符号引用与写操作方式；一次精确字符串无命中不足以证明不存在。
- 已有来源足以解释当前步骤和风险后继续推演；只有新增依赖、冲突或关键副作用不清楚时才扩展阅读。

## 2. 建立贯穿全程的场景

构造明确标记为模拟的 C1 分类、W1/W2 等词、L1/L2 课程和 T0 时间；使用合法词表/选项数量与字段。需要失败、到期和新词时分别说明进度事实，不能在中途偷偷改前置数据。

用统一账本记录：

| 步骤 | 课程/题目身份 | 执行前状态 | 操作与实际分支 | 写入/播放/导航 | 执行后状态 | 证据 |
|---|---|---|---|---|---|---|

模拟 SQLite 值不发送到用户真实数据库；运行验证前自行核对测试库路径与隔离配置，核实隔离后执行适用检查。

区分持久化状态、课内状态、UI 派生状态与播放请求身份；页面显示完成不能直接记为数据库保存成功。需要跨课比较时，沿用同一模拟账本和明确时点，不另造与上一课矛盾的进度。

## 3. 正常主线

1. 从 Home 实际点击入口追到设置、词表加载、进度读取与生成计划；核对当前策略、身份、时间和 seed。
2. 首词展示、自动播放、有效曝光、手动正常/慢速与 Next：明确请求开始、完成、失败降级和按钮锁分别如何变动。
3. 进入测验，计算选项、首次正误与 practiceOnly；追 engine → service → DAO 事务 → 返回 → UI 状态，不能省略保存等待。
4. 触发一次错误，更新账本后继续选对，按队列检查间隔题、重试上限与长期状态是否被重复提高。
5. 最后一题追到保存、延迟、stop、替换路由与完成语音；检查课程完成事实由哪里产生。
6. 分别走 Home/More，再以同一分类进度创建 L2；核对是否同分类、排除与到期优先级，以及两课状态隔离。

每步说明实际输入、条件判定、返回值、异步等待、状态写入与下一步可达性。找不到实现记为断点，不靠产品常识补全。

遇到断点先判断原因：模拟输入不满足已知约束时修正并记录理由；合法操作被实现阻断时保留最后有效快照，继续审查可独立求值的支线。不得假定失败操作成功来推进账本。

## 4. 从明确快照分叉异常

按风险选取，不要求机械穷举：

- 开课读取失败、空/过少选项、设置未加载；失败后能否重试。
- 首播未完时重播、快速 Next、播放完成迟到或播放器初始化失败。
- 首次作答保存延迟/失败/重复提交，不能把页面锁当数据库幂等。
- 错题位于尾部时补题、同课再错、达到重试上限；练习题是否重复影响长期进度。
- 鼓励播放中离开路由、最后一题退出、庆祝语音与 More 新实例重叠。
- More 回调异常、连续点击、后台停留/返回、进程退出；未实现恢复要明确写出。
- Word Library 的自由播放是否改变课程进度/默认轮换，或仅记录辅助听到信号。

涉及竞争或幂等结论时，至少展开一种具体交错：A 读旧状态 → B 读旧状态 → A 保存/切题 → B 完成 → 检查 token、条件更新、事务和数据约束。仅有前端禁用不能证明幂等；纯展示范围不机械增加竞争场景。

## 5. 证据不足与阻塞

- 需求含义不明：先检索确认来源，仍未知时标记该项待核对；若决定后续实施方向才针对该问题询问，独立静态审查继续。
- 关键源码不可读、依赖不在仓库或入口无法确定：明确缺失来源和受影响结论；不要用模拟行为填补证据。必要时询问，先交付可确定部分。
- 环境不可用：仅运行结论受阻，静态分析继续；未实现流程是发现，不是停止整项审查的理由。

## 6. 完成与交付

本次范围内的主线、关键副作用和高价值异常分支都有证据或明确断点后，汇总结果。仅对影响结论的疑点追加最小验证；不机械运行全量测试或扩大到未授权环节。

每个问题说明触发条件、事实与预期、后果、可恢复性、依据和修复方向，合并同根因；优先级按实际影响与证据强度解释，不能把理论可能性直接定为严重缺陷。按覆盖的开课、队列、保存、播放交接或下一课分别给出静态结论；静态无阻断写“未发现静态阻断”，不写“已证明运行正确”。

完整流程账本通常需要可复查报告；按指定位置保存唯一完整版本，无指定时可用 `docs/reviews/learning-flow-YYYYMMDD-HHmm-agent.md`，不覆盖已有文件。小范围审查可在对话交付，遵循用户产物要求及根规范。报告包含范围/基线、相关账本、异常分支、发现和未覆盖项；摘要先说明主要结论、依据与关键限制。按记忆协议判断是否留索引/踩坑/Daily。
