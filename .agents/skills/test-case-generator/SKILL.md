# 目标与范围

用最低合理成本发现具体错误，只保留值得长期维护的测试。遵守根 [AGENTS.md](../../../AGENTS.md)，具体入口见 [验证指南](../../../docs/guide/verification.md)。本技能参考 hdims 的验证策略，执行环境改为 Flutter、SQLite FFI 与现有 Node 工具。

适用于选择验证方式、评估存量保护和执行已授权的验证改动。普通功能问答无需启动测试审查；完整学习流程的状态推演使用对应流程审查技能。

## 开始：输入与工作模式

| 必要信息 | 自行查找的来源 | 信息不足时 |
|---|---|---|
| 本次目标与范围 | 完整对话、指定问题／文件、相关 Git 差异 | 不把工作区所有改动都当本任务；范围影响结论且无法推定时才询问 |
| 预期与故障后果 | 已确认需求、业务契约、历史复现或独立样例 | 标注待核对，不用当前实现输出补造预期 |
| 已有保护与执行条件 | 相关测试、验证指南及实际工具配置 | 先查可复用入口；缺环境只阻塞依赖它的验证 |

仅评估时给出保留、合并、补充或替换建议及依据；是否运行检查由疑点价值和用户限制决定。已授权补测或修复时，选择方式后继续完成必要改动与验证，不停在建议。沿用根规范的任务边界与已有授权，不因切换步骤重复确认。

按本次风险读取相关章节；确定目标、预期和已有保护后进入选择，不为填满检查表收集所有模块。允许不新增永久测试，不等于免除必要验证。

## 1. 先判断增量价值

1. 可能错在哪里：具体输入/操作、错误行为和业务后果。
2. 正确答案来自哪里：已确认需求、历史复现、独立核算或可信样例。
3. 已有检查缺什么：相关用例、静态分析、资源验证或设备验收是否足够。
4. 怎样验证最划算：运行边界、环境、维护成本与下次复用价值。

| 选择 | 适用条件 | 交付 |
|---|---|---|
| 不新增 | 已有保护足够或不涉及需单独保护的行为 | 执行适用检查并说明依据 |
| 一次性验证 | 本次风险明确但长期场景不稳定 | 临时脚本/人工设备检查，留结果和局限 |
| 永久测试 | 明确、可重复且值得防回归，现有检查不足 | 优先扩展已有文件，新增最小保护 |

不因为“函数公开”“模块复杂”或覆盖率不足自动生成整套测试，不为普通文案/可逆布局变更写镜像用例。

## 2. 独立预期与真实边界

- 不把调用当前实现得到的输出抄成 expected，不在测试里复刻同一套算法。
- 只有现状代码依据的重构保护标注“兼容行为保护”，不能宣称产品规则已证明正确。
- 规则冲突先查来源；只阻塞相关预期，其他可执行检查继续。
- 失败区分实现、测试、需求变更和环境，不能只为全绿删断言、跳过、吞错或修改预期。

| 风险 | 最小合适边界 | 无法替代它的证据 |
|---|---|---|
| 选词/晋级/间隔/时点 | 纯 LearningEngine，固定输入/时间/seed | 复制公式或只比较两次输出 |
| Word 映射、题目选项 | 生产 LessonSessionService 可控输入入口 | 仅 engine 返回 ID |
| 重试间隔/上限与尾部补题 | LessonQuizController 结果，必要时页面消费 | 只验证队列长度 |
| 页面等待、锁定、失败恢复 | Widget 交互，可控 Future/Completer | 只验证工具函数或回调被调用 |
| SQL、事务、迁移和幂等 | 隔离真实 SQLite，回读值/结构/约束 | mock DB、匹配 SQL 字符串 |
| 声音串行/中断/生命周期 | 真实服务的可控播放器边界 + 适用设备 | 页面 fake 或语音权重 Map |
| 资源引用 | 生产配置与真实文件/声明 | 只有文件名列表 |
| 图意、发音、插件出声 | 代表样例人工查看/试听和设备 | 文件存在或 PNG/WAV 文件头 |

mock 只隔离无关依赖，不替换本次要证明的行为；内部调用断言仅在调用遗漏/重复会造成具体后果时保留。

## 3. 永久测试准入与缺陷回归

- 断言外部可观察的状态、结果与副作用；不绑私有布局结构、普通文案全文或偶然方法顺序。
- 为明确缺陷新增回归时，在临时副本或隔离环境让旧行为/等效故障使断言变红；失败必须来自目标错误而非加载/编译失败。
- 环境或成本不允许变红验证时写明原因与替代证据，不把“测试通过”扩大成已证明能防回归。
- 不为测试方便大改架构，优先使用已有输入/注入点。默认 legacy LessonPlan 和生产 v2 路径需要明确区分。
- 现有 UI 测试中的辅助进度错误不能被报告为已落库；测试数据库目录必须确认隔离，不能删真实学习库。
- 同类已发生错误跨任务复发且能可靠机械检查时，再考虑守卫；不要把任意格式或可自由调整实现写成永久禁令。

## 4. 存量测试审查

逐项判断能捕获什么错误、是否重复、合法重构成本和实际预期。不能仅因用了 mock、写在实现之后或从未失败就删除。删除保护前确认规则失效、已有等效替代或重复检查。

## 5. 执行、阻塞与完成

复用 Flutter test、sqflite_common_ffi 和 Node test runner；按验证指南执行，不为本技能引入框架或全套 E2E 工程。检查定向命令实际选中了哪些用例，代理连接故障不能冒充断言失败。

- 预期冲突时先查已有确认来源；仍不明确的断言留为待核对，继续独立检查。不能靠放宽断言消除冲突。
- 环境不可用或检查未实际执行时，列出阻塞边界、已完成部分和继续条件；替代证据写清能观察什么，不能将跳过项视为通过。
- 评估完成：每个影响建议的风险都有预期依据、已有保护判断和验证选择，依据不足的项明确标注待核对。实施完成：授权改动和适用检查完成，目标缺陷已处理；无法完成的部分明确标注阻塞与继续条件，不仅凭解释失败宣称完成。
- 目标风险已有足够证据且相关检查通过后结束；只在新变化、失败或未决疑点影响结论时扩大或重跑，不因覆盖率或用例数继续扩张。

交付先给选择与结果，再简述保护的风险、依据、实际验证和剩余缺口。按根规范决定是否保存报告；简单评估可直接在对话交付，必要时同步业务／状态文档与记忆。
