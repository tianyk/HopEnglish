## 4. 记忆机制对齐

HopEnglish 的根 §0.1 与 hdims 相同，唯一领域措辞差异是敏感信息由患者明细改为儿童/家长个人信息和学习明细。

| 机制 | 两项目共同约定 |
|---|---|
| 分工 | Daily 事件、Pitfalls 规则与证据、Summary 决策索引、Playbooks 场景步骤 |
| 开始 | 相关 Summary/Pitfalls/Playbooks → 最近 3 条 Daily → 最近相关最多 5 条与来源 |
| 结束 | 必须判断增量，不强制凑记录；一次交付最多一条 Daily |
| Daily | 东八区实际时间，默认 1–3 短条目，建议 ≤200/硬上限 300 字符，只追加 |
| Summary | ≤15 条、全文含来源 ≤2200 字符、单条 ≤180 |
| Pitfalls | ≤20 条，原因/证据/Seen；不同日期 ≥3 次后提请晋升 |
| Playbooks | ≥3 次复发或用户要求沉淀，3–5 步，≤6 篇/3000 字符 |
| 整理 | 从游标之后新增 ≥20 条、距上次 ≥30 天或超预算；不自动改写 Daily |
| 权限/可信度 | 记忆不替代现场证据，不授予提交/数据库操作等权限，不混写两个项目业务 |

实际记忆入口见 [.memory/SUMMARY.md](../.memory/SUMMARY.md)；未来维护按根协议，不在本规划另外定义不同限额。
