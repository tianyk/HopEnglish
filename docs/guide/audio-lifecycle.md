# 音频时序、所有权与生命周期

业务要求来源：PRD 声音反馈；工程接口：`lib/src/services/audio_playback_service.dart`。本指南将真实 API 语义与需满足的调用约束分开。

## 1. API 的真实含义

| 方法 | 当前实际行为 | 调用方不能推断 |
|---|---|---|
| `playWord(..., waitForCompletion: false)` | 等待 player.play 返回，核对 token 后返回 bool | 声音已完整播放或孩子已听完 |
| `playWord(..., waitForCompletion: true)` | 等待完成事件，4 秒超时；被新 token 替代返回 false | false 都是同一种故障 |
| `playEncouragement/playCompletion` | 先 stop，再播选中语音并等完成，最多 3 秒；失败记日志 | Future 完成必然表示音频成功播完 |
| `stop` | 使 token 失效，等待初始化并 stop | 自动释放播放器 |
| `dispose` | 使 token 失效，等待初始化结束后释放 player | UI 可以再使用此实例 |

表中布尔结果是 `playWord` 的返回值；void 方法无成功标志，调用方不得用“Future 正常返回”替代已出声的证据。

`playWord` 失败路径按总耗时补足至 1200ms 后返回 false（仅等待模式）。这是交互降级等待，不是成功播放证据。boolean 同时表达成功与请求仍有效，后续改接口时应保持调用方语义清楚。

## 2. 现有所有权

| 调用方 | 当前实例策略 |
|---|---|
| WordLearningPage | 默认创建服务；注入 audio 时不释放外部实例 |
| WordExplorePage | 页面创建并在 dispose 中释放 |
| CelebrationPage | 页面创建并在进入时播放一次完成语音 |

服务 token 是**单实例**机制，不能防止不同页面实例重叠播放。学习页进入庆祝前显式 stop，但其他路由交接仍需结合实例释放与平台行为验证。当前没有全局音频调度器，不能仅凭一个 token 字段认定“全 App 单人声”已验证。

## 3. 时序契约

- 自动首播完成或明确降级后才能解锁当前学习步骤；之后手动重播不应重新锁住已经可用的 Next。
- 首播期间的手动播放接管当前等待，旧播放完成不得解锁另一题或新画面。
- 普通答对等待鼓励阶段结束，再进入下一题播放；最后一题跳过普通鼓励，由庆祝页播放一次完成语音。
- 任意时刻仅一条人声；普通语音和完成语音不叠加。页面和服务双方分别处理操作身份与播放身份。
- 正常/慢速来源以模型路径和明确后缀约定为准，不能每次临时改速导致不一致。

## 4. 前后台与释放

涉及播放或曝光代码时必须说明：离开路由、锁屏、切后台、快速返回和 dispose 后迟到回调分别如何处理。

- UI 存活检查不能代替音频 stop/cancel；取消 Timer 也不能取消已开始的播放器操作。
- 切后台后的曝光是否有效需按计数契约判断；当前没有显式 AppLifecycle 观察，不能以系统默认暂停行为证明统计正确。
- `unawaited(dispose())` 只有在错误已处理且所有权交接明确时成立。跨页面“旧实例释放 + 新实例播放”的竞争需用可控延迟和设备验证。
- 不为本指南自行引入后台音频、自动续播或恢复课程；这些都是产品行为变化。

## 5. 网络和慢速限制

Word 模型能表示网络音频，但当前 slow + 网络分支会进入 AssetSource，未实现完整远程慢速音频契约。随包词表使用本地 WAV；网络能力需单独实现和验收，不在内容文档宣称开箱可用。

## 6. 选择验证

- 页面替身用可控 Completer 检查等待、重播、停止、换题和导航顺序。
- 服务层若改时序，验证真实服务对 player 完成、stop、超时、初始化失败和 dispose 的反应，不只断言权重配置。
- iOS 设备检查首播、连点、慢速、鼓励与完成交接、后台返回及系统音频中断；Widget 全绿不能证明插件行为。
- 断言“只有一条声音”时明确检查的是一个实例、跨页或全 App，不扩大证据范围。
