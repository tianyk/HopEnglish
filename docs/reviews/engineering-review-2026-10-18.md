## 1. 结论与优先顺序

上一轮已建立规范、指南、状态、技能和记忆的基本结构。继续优化的主要收益在于减少多处维护、使工具准确执行协议、提高评审的可复查性。文件数量和参考项目的篇幅不适合作为完成标准。

| 顺序 | 建议 | 相比上一轮的增量 | 最小实施范围 |
|---|---|---|---|
| 先做 | 收敛事实与问题状态的重复记录 | 已出现分散登记：设置保存问题在指南内，E 编号表未收录 | 让指南保留稳定契约与接口，具体缺口统一引用实施状态 |
| 先做 | 校准文档检查器 | 已复现链接/日期漏检，以及把默认建议硬化为失败 | 修正对应检查项和输出范围，保留最小故障样例 |
| 先做 | 补强流程审查技能 | 缺少否定结论的搜索证据、断点继续规则、问题判级依据 | 扩展现有技能中的少量规则，执行一次真实入口的静态推演验证可用性 |
| 随后 | 分开单课与跨课两条审查时间线 | 现有技能覆盖 L2，但没有明确要求跨复习时点连续回读 | 复用当前纯决策与隔离 SQLite，按需要保护跨层行为 |
| 随后 | 补齐错误恢复与诊断契约 | 已写失败恢复要求，尚缺统一失败分类和操作关联上下文 | 随开课/保存/音频修复补齐现有指南与 Logger 调用 |
| 随后 | 将既有检查接入自动化 | 已在原计划中，仍是高收益实施项 | 本地入口与 CI 复用，校验成功后才进入适用构建阶段 |
| 按需 | 建立视觉状态样例与截图来源记录 | 画廊已列缺口；本轮补充状态覆盖和证据追溯方式 | 从真实组件的少量状态开始，商店截图另记版本/设备/状态 |

本表的“先做”仅是这轮体系维护的顺序，不将文档问题评级为严重运行故障。应用缺陷的优先级仍按业务影响判断。

## 2. 让事实和问题只维护一次

**代码与文档事实：** legacy 页面测试的局限同时见 [学习指南](../guide/learning.md)、[UI 指南](../guide/flutter-ui.md)、[验证指南](../guide/verification.md) 与 [实施状态 E-06](../product_status.md)。音频单实例 token、数据库隔离也在多个位置展开。适量入口提示有用，但重复记录当前缺陷会增加关闭问题时漏改的概率。

已有一个具体遗漏：[组件指南](../guide/components.md) 记录了设置回调先于保存成功，当前 [LessonSettingsSheet._select](../../lib/src/widgets/lesson_settings_sheet.dart) 确实依次执行 setState、onChanged、await 保存；实施状态 E-01～E-12 未单列这项。若仅按状态表安排修复，可能漏掉设置失败恢复。这里是静态顺序与文档归属的核对，未注入保存故障。

建议沿用现有文档分工：指南保留稳定方法、接口语义和必要限制；临时缺口在实施状态记录触发条件、当前状态与关闭证据，其余位置链接到该项。历史检查结果留在报告或 Daily。计划引用状态项安排工作，不再复制问题细节。

同时区分“确认的实现缺口”“待验证风险”“有意保留的能力边界”。例如未承诺跨进程恢复时，E-11 的恢复限制不宜与 More 异常锁定视为同一种待修复缺陷。关闭条目保留日期与证据，不只从列表删除。

最小验收：抽取设置保存、legacy 测试、音频交接三个主题，能从任务入口找到唯一的当前状态和对应依据；关闭一项时无需在多份指南手动重复修改完整描述。

## 3. 文档检查器要验证真实失效模式

参考来源：hdims `.agents/skills/product-manual/scripts/validate_manual.js` 会构建标签和引用集合，检查未解析引用、重复标签和未注册章节。值得借鉴的是引用关系校验；TeX 结构和图片去重规则不直接用于 Flutter 文档或共享音频。

本次调用 [check_docs.py](../../tool/check_docs.py) 的生产检查函数，在临时目录构造样例，结果如下：

| 输入 | 当前结果 | 解释 |
|---|---|---|
| `[target](missing.md)` | 拒绝 | 已有能力有效 |
| `[target](target.md#missing-heading)`，文件存在但章节不存在 | 接受 | 只验证文件存在，没有验证 fragment |
| `[target][ref]` 加 `[ref]: missing.md` | 接受 | 引用式链接不在当前正则匹配范围 |
| 行内代码 `lib/src/missing.dart` | 接受 | 当前主动跳过行内代码，不能由“检查通过”推断所有源码引用有效 |
| `2026-99-99` 与 `99:99`，Daily 游标能匹配标题 | 接受 | 只检查数字格式，没有验证日期/时间有效性 |
| 四条很短、总长度未超 300 字符的 Daily | 拒绝 | 脚本把根协议的“默认 1–3 条”当作硬性上限 |

后四类遗漏或限制并不表示当前仓库已存在全部这些错误；它们是已复现的检查能力边界。上一轮的正向结果仍成立，但不能扩大为完整 Markdown 或记忆语义校验。

建议优先支持实际使用的 Markdown 链接形式、有效日期/时间，以及与协议一致的软硬约束。默认条目数适合提示，300 字符硬上限仍应阻断。纯锚点与文件内锚点采用明确的标题 slug 规则，对无法可靠解析的形式给出边界说明。

源码路径不宜对所有反引号内容一刀切校验，目录简写、旧接口反例和占位符都是合法内容；可先把需要机器验证的真实路径改成链接。将少量确定的漏检/误判样例保留为检查器回归，防止校验逻辑继续偏离规范。

hdims 也有文档漂移实例：其 AGENTS 与主题指南仍引用 `apps/web/src/pages/ThemeSpecPage.tsx`，实际文件在 `apps/web/src/pages/spec/ThemeSpecPage.tsx`，`App.tsx` 从后者导入。参考来源必须复验，不能直接把参考项目的路径或完成声明抄过来。

## 4. 把流程审查方法补到可以稳定复查

参考来源：hdims `.opencode/commands/flow-review.md` 的证据纪律、主线断点处理、并发证据层次和问题判级。当前 [learning-flow-review](../../.agents/skills/learning-flow-review/SKILL.md) 已保留主线账本、异常快照和一次竞争交错，但还有几个有效约束没有带过来：

1. **“未找到”也要有证据。** 写明搜索目录、符号引用与写入方式；不能一次精确字符串无命中就断言能力不存在。
2. **断点后的继续方式。** 区分模拟输入不合法与合法操作被阻断；后者保留最后有效快照，继续检查独立支线，不能假定失败操作已成功。
3. **问题判级依据。** 用触发条件、影响、可恢复性和证据强度解释优先级；不能把理论竞争直接写成严重缺陷。
4. **状态类型分开。** 当前题索引/按钮锁、课程身份、SQLite 掌握状态和 UI 派生进度分别记录，避免画面完成被视作持久状态完成。
5. **按边界判定结果。** 开课、课内队列、保存、音频交接、下一课分别给出结论与未覆盖项。

可直接扩展现有技能，暂不另建大套审查模板。此次 `docs/reviews/learning-flow-*.md` 搜索未找到本仓库的已保存推演报告；技能还需要通过一次真实任务检验，不能仅凭文件存在宣称审查流程已成熟。

## 5. 单课与跨课使用两条时间线

hdims 分开“单次透析”和“多次治疗构成的历程”，因为一次完成不能证明跨次状态正确。HopEnglish 对应两种边界：

- 单课：首播、重复播放、首次作答、错误纠正、重试、保存、庆祝、More。
- 跨课：持久化后的掌握状态、下次到期、再次选入、同课晋级限制以及跨课程身份隔离。

当前技能已要求 L1/L2，却未明确跨到期时点推进；[learning_engine_test.dart](../../test/learning_engine_test.dart) 的多阶段验证分别构造状态调用 applyAttempt，没有构成“课程 → 保存 → 回读 → 后续课程”的同一条证据链。这不是否定已有单元测试的价值，而是说明另一条边界尚需独立观察。

建议按 [学习算法](../learning_algorithm_v2.md) 中已确认规则选择代表场景：T0 初次正确后持久化，T0+1 天前后回读并观察下一次选词优先级，再验证后续阶段；时间、随机和输入可控。练习题不重复提高长期状态、同课不能再次晋级，分别看纯决策与真实写入是否一致。

最小范围是能观察缺失后果的一个连续场景，不机械补齐每个字段或每种排列。发现需求不明确时标注，不能将当前实现输出直接写成预期。

## 6. 错误恢复与日志需要共同设计

参考来源：hdims 的 `apps/server/docs/guide/error.md`、`log.md` 与实际 `utils/log.js`。可借鉴统一的错误语义、等级与请求关联，按移动端现有接口适配。

当前 [UI 指南](../guide/flutter-ui.md) 有 try/catch/finally 示例，但日志和重试 UI 仍是占位注释。[LearningProgressService.recordLearningAttempt](../../lib/src/services/learning_progress_service.dart) 记录错误/堆栈后重抛，未携带课程版本或操作标识；页面 `_recordAttempt` 捕获后返回 null。[音频服务](../../lib/src/services/audio_playback_service.dart) 已有资源和播放器状态上下文，说明现有 Logger 可以承载必要字段，无需为此先引入新平台。

建议围绕开课失败、关键保存失败、音频超时、被新操作取消、内容缺失几个已有边界，约定是否阻止推进、如何重试、由哪层记录日志。特别是超时与主动取消，不宜全按同一错误处理；重试保存需先明确重复写入语义。

诊断字段只收集必要的操作名、策略版本、失败类别和本次操作关联标识。调试用模拟场景可使用课程标识串联，不在文档、记忆或默认日志中累计真实儿童的完整学习轨迹。[Logger](../../lib/src/libs/logger.dart) 已支持 data/error/stackTrace；生产日志等级和输出策略应在相关修复时一起核对。

最小验收：故障后能知道失败发生于哪个操作边界，UI 可继续采取合理动作，日志不会重复堆同一异常。无需照搬 HTTP 状态码体系、服务端日志文件方案或整个异常类树。

## 7. 自动化与视觉证据如何借鉴

**自动化是已有待办。** hdims `.github/workflows/build.yml` 使用独立 verify job，package 显式 `needs: verify`；但触发条件是 push 到 main/master 和手动触发，不包含 pull_request。因此可以借鉴阶段依赖，不能宣称其已有 PR 校验配置可直接照搬。

HopEnglish 目前无 `.github/workflows/` 工作流。结合既有 [工程计划](../engineering_optimization_plan.md) 先收敛本地检查入口，按变更范围调用文档、Dart、资源与工具检查；CI 复用入口，适用的 iOS 编译/Archive 使用 macOS 环境。签名上传与验证分开。无需复制 MySQL 服务、Docker/COS 出包或 hdims 的自动通知。

**视觉状态样例是已有缺口的具体化。** hdims 的实际 `pages/spec/ThemeSpecPage.tsx` 和 spec 路由把主题、真实组件和状态放在可访问页面中；手册截图指引还要求真实状态、逐张原图复核、最终产物回查。

HopEnglish 可先做仅用于开发/验证的最小样例，使用真实 AppTheme/组件展示播放锁定、可重播、选错、加载/失败、长单词、小高度等状态，随相关 UI 迭代加入。组件尚未抽取时先通过真实页面验收，不为画廊复制第二套按钮实现，也不默认增加新依赖。

商店截图可在现有资源说明中记录构建号、源码版本/在途差异、设备/逻辑尺寸/像素尺寸、页面状态与采集日期；逐张查看原图。开发样例可用明确标注的模拟状态，商店材料应来自真实应用流程，两种证据用途不同。当前截图是否过时以及 App Store 当前规格，本轮没有视觉或在线核验。

## 8. 这轮不值得扩大什么

- 四层记忆的 A–G 协议已对齐，先改进执行准确性；暂不增加第五层、自动摘要或向量检索。
- 现有指南数量已足以覆盖当前模块；新内容优先归入已有章节，仅在独立职责形成后拆文件。
- 不根据模块数量机械新增测试、守卫或公共组件。hdims 的客户文案守卫有具体历史缺陷和有限扫描范围，这一准入原则值得保留。
- 不搬入 React hooks、Express 异常树、医疗权限流程或通用工作流引擎；它们不解决当前 Flutter 项目的具体问题。
